# 产品指南

如何在当前控制台中以财务 / 应付（AP）用户身份操作 AVENZA。

## 账号与工作区

1. **创建账号**（`/register`）— 姓名、邮箱、密码。
2. **创建工作区**（`/workspace/new`）— 组织法定名称（需要会话）。
3. **登录**（`/login`）— 存在组织时打开 `/app`。
4. **退出** — 顶栏控件清除 JWT 与组织选择。

应用内文档位于侧栏 **文档**（`/app/docs`）（与公开 `/docs` 内容相同）。

## 概览

- 问候语 + 待关注数量
- KPI 条：待审批、审核中、可付款、未结应付
- **资金钱包** — 复制地址、区块浏览器、充值至金库
- 图表：按状态的付款、按账龄的应付
- 队列 + 近期发票 + 下一到期 + 快捷操作（**付客户**、**批量付款**、**上传**、**注资**）

充值打开注资弹窗：向资金钱包发送 **原生 USDC**（+ OKB 作 Gas），再存入 `BusinessTreasury`。

---

## 收款方

1. 登记收款方（法定名称）。
2. 添加目的地：链、原生 USDC 代币、钱包。
3. 结算前 **验证** 收款方与目的地。

仅地址的直接付款会创建 **待处理** 收款方 — 结算前必须验证。接入注册表时会检查链上 `VendorRegistry.isEligible`。

---

## 发票

1. **新发票** — 上传文档。
2. 抽取辅助审核（`EXTRACTION_MODE`）；不授权资金。
3. 核验字段 → 就绪后提交审批。
4. 详情：`/app/invoices/[id]`。

敏感抽取 JSON 静态加密存储（字段加密）。

---

## 审批

1. 按需配置审批层级。
2. 审批人 **通过** 或 **拒绝**。
3. 双控：当 `requiredApprovals > 0` 时，付款 UI **不会** 自动通过 — 请先使用本队列。

Partner API 密钥可提交审批但 **不能** 决策（仅控制台 JWT）。

---

## 付款

三种创建模式：

| 模式 | 流程 |
|------|------|
| **发票** | 已审批发票 → 授权（TapeOut）→ 执行 |
| **直接** | 已验证收款方/地址 → 创建 → 如需则审批 → 授权 → 执行 |
| **批量** | 批量行 → 如需则审批 → 结算各行 |

涉及真实资金的重要规则：

- 结算需要合约 + relayer；否则模式为 **blocked**。
- 结算失败后，**在同一笔付款上重试 execute** — 勿新建付款（避免双付）。
- 确认数：`REQUIRED_CONFIRMATIONS`（主网建议 ≥ 3）。
- **费用：** 每笔结算从组织金库扣除供应商金额 **以及** 平台费（bps + 固定）与 gas 回收 USDC（`PLATFORM_FEE_*` / `GAS_RECOVERY_USDC_MINOR`）。Relayer 仍支付 OKB gas；你在 USDC 中回收成本与利润至 `PLATFORM_FEE_RECIPIENT`。

---

## 管控

- 发布 **管控** 区间（自动 / 单人 / 双控 / 暂挂）。
- 发布绑定 TapeOut 处理器 + 电路 id 的 **付款策略**。
- 授权时使用活跃策略；链上再评估需要非零处理器。

## 设置

| 标签 | 内容 |
|-----|----------|
| 工作区 | 组织资料、网络、金库余额、注资 |
| 开发者 | Partner API 密钥（`avz_live_*`）+ 作用域 |
| 集成 | ERP 连接器、Webhook |
| 人员 | 成员 / 角色 |
| 活动 | 审计事件 |

值得注意的 Partner 作用域：`payments:initiate`（创建/授权）、`payments:settle`（执行）、`approvals:submit`（仅提交）。

---

## 操作员清单

1. 以 admin 登录。  
2. 为金库注资（概览 → 充值）。  
3. 验证收款方与目的地。  
4. 上传 / 核验发票（或使用直接/批量付款）。  
5. 需要时取得双控审批。  
6. 从付款页授权并执行。  
7. 确认浏览器链接与状态。  
8. 若授权后结算失败：为金库注资 → 在**同一笔付款**上重试 **execute**。
